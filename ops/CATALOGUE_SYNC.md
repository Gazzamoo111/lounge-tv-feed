# BEST catalogue synchronisation

The serving gateway remains the existing Xtream Worker. The workflow reads the
active R2 release and writes a new immutable catalogue release when reconciliation
changes the output. The Worker, customer records, provisioning UI and EPG workflow
require no configuration or code changes.

## Workflows

- [Catalogue sync](https://github.com/Gazzamoo111/lounge-tv-feed/actions/workflows/catalogue-sync.yml)
- [Catalogue validation](https://github.com/Gazzamoo111/lounge-tv-feed/actions/workflows/catalogue-sync-validation.yml)
- [Current EPG refresh](https://github.com/Gazzamoo111/lounge-tv-feed/actions/workflows/xtream-production-epg-refresh.yml)

Events run hourly at minute 17. Permanent channels run daily at 04:47 UTC
(17:47 NZDT or 16:47 NZST). Default-branch schedules publish only with the
repository variable `LTV_BEST_CATALOGUE_SYNC=enabled`. Validation branch pushes
run read-only against the production R2 baseline. A branch commit marked
`[catalogue-inventory]` also runs the authorised BEST and D1 read-only overlap
report. It prints source group IDs and counts without provider credentials, raw
stream names or source URLs.

## Secure inputs and isolated acceptance

Use the existing GitHub Actions environments
`lounge-tv-xtream-production-refresh` and `lounge-tv-xtream-qa-refresh`.
Set `BEST_SYNC_ORIGIN`, `BEST_SYNC_USERNAME` and `BEST_SYNC_PASSWORD` as
environment secrets using a durable BEST line entitled to the approved bouquet.
The origin is the provider's base URL with no path or credentials. HTTPS is the
default and redirects are rejected. Set `BEST_SYNC_ALLOW_HTTP=true` only if
that specific provider route is already approved for the inventory job.
Reuse the existing R2 credentials. The D1 query credential is
`LTV_CATALOGUE_D1_TOKEN` or the existing environment `CLOUDFLARE_API_TOKEN`.
The script queries only `stream_ids`; it does not read the customer table.

Use the authoritative readback for the target bucket. Store its verified
`catalogue-sync/policy.json` in that private bucket. The policy shape is:

```json
{
  "bucket": "<target private R2 bucket>",
  "categories_sha256": "<SHA-256 from the target baseline run>",
  "eventTarget": "<existing final Lounge TV category ID>",
  "groups": {
    "<BEST group ID>": {
      "sourceName": "<exact provider category name>",
      "target": "<existing Lounge TV category ID>",
      "targetName": "<exact Lounge TV category name>"
    }
  },
  "minimumGroupCounts": { "<BEST event group ID>": 100 },
  "excludedIds": [],
  "protectedIds": [],
  "maxChanges": 1000
}
```

Use observed group densities to set floors, and catalogue overlap to verify
unambiguous mappings. Review groups that mix approved and excluded content before
enabling them. Include explicitly suppressed IDs absent from the D1 allowlist in
`excludedIds`. Include any independent source or override IDs in `protectedIds`.
Historical D1 entries omitted from the visible catalogue are suppressed
automatically. Unknown groups remain pending. A single missing response reports
absence. An unmapped, unprotected event can age out after three consecutive
complete hourly observations. Permanent channel disappearances and category
changes always require review.

Run `inspect` for `events` and `daily` before publishing in isolated QA. Use
environment-specific credentials and a QA policy that matches QA assets. Verify
new ID registration, D1 route and genuine playback with an authorised QA account.
Refresh the Xtream playlist on Nuvio, find the new event in the Sports Hub,
check Freeview/Sky and current/next, then rehearse the rollback in QA.
Set the production enable variable after those checks pass and verify the first
scheduled runs. Private `catalogue-sync/latest-report.json` records changes and
pending categories after a successful publish operation.

## Publication and rollback

The workflow validates JSON/M3U parity and preserves the frozen production EPG
mapping contract. It stages and hashes all catalogue objects, verifies additive
D1 registration and conditionally changes the shared `current.json` using its
read ETag. A concurrent EPG write causes a stale catalogue publication to fail.
The next run reads the latest pointers. Existing URLs and IDs remain in the
catalogue unless an unprotected stale event meets the repeated-absence rule.

Disable scheduled publishing by clearing `LTV_BEST_CATALOGUE_SYNC`. Wait for
any running catalogue job, then dispatch the sync workflow with
`operation=rollback` and `expected_release` set to the active sync release.
Rollback restores its recorded parent catalogue and carries forward whichever
EPG is active at rollback time. D1 registrations are additive and retained for
client caches and recovery. Releases generated by this workflow are bounded by
a 768 MB storage cap. Pruning applies to sync releases older than 72 hours and
keeps the active release, its direct parent and active/previous guide pointers.
The pre-sync production catalogue is outside that pruning scope.
