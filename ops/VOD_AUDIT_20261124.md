This limits the freshness and availability claims. The production and QA gateway checks use the same dedicated catalogue line. ## Gateway behaviour

- Production `n` v39 returned HTTP 200 for both lists and both category actions. The sampled detail actions returned HTTP 502 `entitlement_unavailable`. Those handlers fetched the corresponding full BEST list before returning an editorial record. The independent supplier checks also failed from the database network. The current supplier catalogue and the exact reason for the supplier's HTTP 451 were not independently verified.
- Production deliberately requires `get.php` fallback for DRM-aware live import. The current M3U contains live entries only. If Nuvio switches the playlist to M3U and skips native Xtream VOD, it receives no titles. The Fire TV's actual import sequence has not been captured.
- QA retains the existing gateway authentication step and returns approved editorial details without a duplicate supplier catalogue request. Media redirects use the customer's assigned BEST credentials and BEST still validates actual stream access. No dedicated catalogue credentials, supplier payloads or alternate customer lines are returned by the VOD actions.
- QA v1 at `https://liqocisegeqzbyuqloql.supabase.co/functions/v1/lounge-vod-qa` is restricted to the owner line and the managed catalogue test line through existing Vault bindings. The deployed bundle `74e55f8a82c1ddaf38a3f2ac7bc0cd55ae32794f056f078a0ab690c16d46a3e1` matched all 17 generated files. All six actions returned HTTP 200. The sampled series detail returned two seasons. The existing live DRM fallback response was identical in behaviour.
- The gateway returned HTTP 302 for one movie and one episode in Edge logs. The database probe timed out after following the redirects. Media playback, seeking, resume, audio and subtitles remain unverified.
- The all-title lists return unique IDs. The per-category API and `category_ids` express multiple memberships. Nuvio may use only the primary genre or may honor the full membership. Check this on-device before promising all featured rows.
- Unverified or underpopulated features were omitted. Only one qualified movie matched 4K and the threshold is three. No qualifying Sitcoms, Lifestyle, Miniseries, Thriller or Horror series category reached the minimum based on the stored classification. The 40 recently updated series had mapped recent episode records. One retained series is available without a supported genre category.

## Client checks

Add the QA URL as a separate Xtream source with the existing owner login. Keep the production playlist and its guides in place. If the test client allows disabling Live TV for that source independently of On Demand, use that toggle to avoid importing duplicate channels during the first VOD check. Refresh the QA source, open On Demand and check one movie and one series episode. Then test seek, resume, a title with multiple audio or subtitle tracks and search. The native app controls sidebar, Home rows, watch history, resume and search. The gateway controls the catalogues, category order, IDs, item detail responses and playback routes.

The release notes under [Nuvio + IPTV releases](https://github.com/homelessbrian/NuvioPlusIPTV/releases) show that M3U On Demand support and IPTV Home rows were introduced after the previously observed `1.2.0-beta.1.4`. On a release that supports them, add the desired categories via Settings → Content & Discovery → Home Screen Rows → Add a row. Preserve the current sidebar settings. Physical Fire TV import, duplicate search result behavior, large-catalogue memory usage, live/sports/EPG playback and VOD track controls remain unverified.

## Operational impact and rollback

The QA request cache reuses a ten-minute per-catalogue build and coalesces concurrent refreshes. It serves the last good in-memory snapshot for the same release for up to thirty minutes after expiry if a refresh fails. The cache recomputes featured rows from the existing approved release and stored metadata. It does not create a parallel catalogue or add a cron job. Existing VOD presence and reconciliation jobs were disabled. Current supplier inventory ingestion and automatic admission of new titles and episodes still require a verified provider response and a safe incremental promotion process.

Recorded database size was 462,425,235 bytes before QA. No new table, scheduled job, paid infrastructure or customer configuration was added. Production remains on `n` v39 and `lounge-plus-qa` v8. Remove the standalone QA function to withdraw the endpoint. The future rollback baseline for a production promotion of the VOD changes is the exact [production n source at 947488d](https://github.com/Gazzamoo111/lounge-tv-feed/tree/947488d573b2ee6429fe9408dd3fbb925552b873/production/n), matched to the deployed v39 bundle. Keep the deployed Plus v8 bundle in place. No production promotion occurred.
