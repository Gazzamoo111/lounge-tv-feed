# Playlist and EPG regression

This suite replays the Phase 1 source for standard NZ/AU (`n` v37), Plus (`lounge-plus-qa` v5 via `n`), and International Regional v4 (`lounge-international-regional-qa`). It uses synthetic catalogue rows, synthetic programme windows at a fixed UTC clock, a fake Vault verifier and stubbed HTTP and database responses. It checks the gateway logic and responses these inputs exercise. Log rows, synthetic channel counts and transport responses are separate from authenticated feed and playback evidence.

## Run the checks

Use Python 3.12 and Node 24. Fetch the Phase 1 revisions listed in the regression workflow once, then run these commands with no network or secrets.

```sh
git fetch --no-tags origin \
  68be2022dc70675c351a8a6fc5435ae1f4079efa \
  589ecddb085352585d3f7d3b6a65ecc2ad444b68 \
  db443bb775bea37a92339db2443b418ea8222386 \
  f8bc7ab33542bda9daedf1839cd23d980f4b6a7c
PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests/playlist_regression -v
PYTHONDONTWRITEBYTECODE=1 python scripts/run_playlist_regression.py
```

The runner reuses the Phase 1 restore verifier and existing routing, grouping and source selection tests. It overlays candidate code using the repository paths identified by the manifest; it prints each overlay applied. Include a proposed source change at its manifest path on the PR branch. Code held solely on a separate branch is outside the current CI inputs. Candidate layouts involving new files or a different entrypoint also need a corresponding extension to the runner. A regional-only PR with an existing Phase 2 base also checks protected NZ/AU and Plus projections against that base. The replay independently verifies International-only inventory never enters the protected profiles.

The expected files are generated by the synthetic replay. Use `--refresh-synthetic` only for an intentional contract change, and review the fixture diff with the source change. The comparison reports category IDs and order, counts, stable channel IDs and order, icon and logo drift, guide mappings and per-channel current and next windows. Duplicate analysis fails repeated provider identities and normalised same-service repeats, preserves explicitly annotated regional variants, and marks ambiguous matches for review. Provider duplicate coverage depends on verified annotations. Category flag and emoji changes appear as label differences.

The validators support a successful Xtream catalogue and the documented 503 plus M3U response. All three replayed profiles expect the latter. TVNZ 1 and 2 direct live requests expect `422 drm_client_required`. The M3U assertions check each DASH and Widevine entry and its existing channel-specific licence route. Sky Sport 1–9 direct requests check the source chosen by each profile. Plus tests check that standard and nonmatching requests fall through and VOD stays on the standard path. Guide replay checks the NZ/AU provider fallback and Regional v4 compiled and shared guide paths.

## Private fixture capture

Use a dedicated authorised QA account for each profile. In one session, export the M3U, Xtream categories, Xtream live stream body and HTTP status, and decompressed XMLTV. Save these as `playlist.m3u`, `categories.json`, `streams.json` and `guide.xml` under an access-restricted directory outside the checkout. Optionally capture `fallback.xml` when that guide branch can be observed safely. Record one UTC comparison time for the export and the serving source revision, function version and guide branch. Keep request headers, credentials, raw captures and this directory private.

```sh
python scripts/playlist_regression.py /private/qa-export \
  --profile nz-au --as-of 2026-11-20T00:00:00Z --stream-status 503 \
  --origin-version 37 --revision "$REVIEWED_SOURCE_SHA" --guide-branch core \
  --capture-private /private/nz-au-projection.json
```

The capture command reads local files only. It creates a new owner-only file with allowlisted structural data and prints aggregate checks. It omits playlist and stream URLs, request credentials, licence targets, URL parameters and paths, programme text, programme metadata beyond windows, and unknown JSON fields. The private projection retains catalogue names and identifiers and stays out of GitHub and Actions. For channels sharing a service identity, supply optional `identities.json` in the private input directory, keyed by stable channel ID with approved `identity`, `region` and namespaced `provider` annotations. Omit values whose provenance is unknown.

Coverage counts eligible playlist channels, excluding 24/7 and unscheduled event categories. A mapped channel has a matching XMLTV channel ID. Current uses a half-open programme window at the supplied UTC instant. Next uses the earliest later start. Missing or placeholder playlist IDs and IDs absent from XMLTV have separate counts. Bad XMLTV references, duplicate XMLTV declarations, invalid timestamps and reversed windows fail validation. Counts describe feed structure and timing, not schedule accuracy or what the player imported.

## Phase 2 evidence and release gate

Local checks on 20 November 2026 NZDT passed 34 reused Node tests, 11 validator tests, the three gateway replays and five guide projections. The replay restored 45 public source files, verified against the Phase 1 manifest. Supabase still reported the manifest's versions and package hashes for all 15 audited functions.

| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| NZ/AU | 25 | 10 | 22 | 20 | 18 | 17 |
| Plus | 25 | 10 | 22 | 20 | 18 | 17 |
| Regional v4 | 27 | 11 | 24 | 22 | 20 | 19 |

Each profile deliberately includes one eligible row without a real guide ID and one ID missing from XMLTV. The two exercised fallback projections returned the same coverage counts as their corresponding primary projections.

Phase 3 release design can use these checks. Keep the release gate closed until authenticated captures, in-app playlist and guide import, protected playback on a compatible Nuvio device and an isolated rollback rehearsal have been recorded. Live endpoint smokes are tracked separately in Issue #10 and are outside this deterministic workflow. The legacy guide workflows and serving code were outside the Phase 2 diff. The recovery reference for protected NZ/AU is the [Phase 1 n v37 bundle](../phase-1/RECOVERY.md).
