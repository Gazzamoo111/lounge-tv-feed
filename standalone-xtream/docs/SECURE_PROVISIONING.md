# Secure customer registration

Owner-only interface proposed at https://tv.loungetv.nz/operator/provision. Uses existing D1, HMAC and AES-GCM bindings; generates distinct Lounge TV credentials in the browser. No credentials stored in browser storage or repository. Create-only inserts prevent silent overwrite. Requires a separate randomly generated 32-byte base64url operator secret named PROVISION_ADMIN_TOKEN in the Worker; never use an existing customer password or publish the token. No provisioning mutation until authorised. Provider entitlement and expiry must be verified by the operator before registration; the form does not validate provider entitlement or enforce provider-side concurrent sessions. Renewals and revocation remain existing manual operations. Do not deploy VOD migration branch. Use the original live-only Worker config; validate existing bindings and retain rollback version 8a90126d-709e-4f18-bd6c-1b631ac05bc4. Candidate must pass existing gateway regression and new auth/crypto/create-only tests before traffic activation. Real customer login and playback remain separate acceptance gates.
